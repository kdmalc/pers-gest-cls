## 0. Corrections to the premises in the request
- **The model does not see sliding windows.** The tensor dict holds *one sample per whole repetition*: `tensor_dict[pid][gesture]['emg']` has shape `(10 reps, 64, 16)`, `['imu']` `(10, 64, 72)` (`maml_data_pipeline.py:9-14`, built in `tensor_saving_with_morphology.ipynb`: `trial_length=64`, `Rows not divisible by trial_length` check, each trial normalised separately). Each rep is time-resampled to 64 steps (EMG as a 20 Hz envelope). So window-overlap/adjacent-window leakage cannot occur *at the model input*. What is **CANNOT DETERMINE** from this repo: whether the upstream "experimenter-defined" segmentation of raw recordings could make two reps overlap in raw time, and whether all 10 reps come from one session (see 4.4).
- **"~320 distinct user-gesture pairs"**: 32 users x 10 gestures. After the new split, 28 users are evaluated (4 are dev-only).

## 2. What the numbers can and cannot support today
- Fixed-split numbers: no test-user labels in training or selection of weights; but inner-steps (1.4) and early-HPO choices (1.3) may have seen test users.
- L2SO numbers: hyperparameters selected on 4 users that are also L2SO test users (1.2); remaining 28 users were HPO *train* users only (weaker issue).
- Both: random-rep support/query within a session (4.4); eval label order fixed (3.3).

## 3. Proposed clean protocol (already adopted as of 2026-10-21 unless noted)
1. 4 dev users for HPO only (P005, P131, P116, P109) — **done** (split JSON).
2. 7-fold subject CV on the other 28, 20/4/4 — **done** (split JSON + `ablation_config.apply_kfold_fold`; wiring in progress).
3. Support/query from disjoint repetitions — already true; add: carry `rep_idx` in samples, run the leak assertion on every test episode, save per-episode rep ids in results JSON.
4. Per-episode label permutation at **test** time — change `use_label_shuf_meta_aug=False` -> `True` at the ~13 call sites (or remove the flag and always permute); keep a fixed seed so every method sees the same permuted episodes.
5. Per-user aggregation for both val and test; select checkpoints on per-user mean.
6. One shared episode generator for *all* methods (neural, `$B`, KNN, ProtoNet, Riemannian, ROCKET): precompute episodes per (fold, user, seed) once, save to disk, and have every baseline consume them.
7. Selection discipline: inner steps, learning rates, epochs chosen on the 4 dev users only; sweeps default PIDs removed (must be passed explicitly).
8. Explicit rep-order ablation (support = earliest reps, query = latest) as a robustness table, to quantify 4.4.
9. Zero-shot cross-user figure: train 10-way on the fold's 20 train users with fixed global labels, test on held-out users with **no support**, report accuracy per user and pooled; chance = 10%. If near 10% the "user-defined gesture" framing is supported; if ~40% it should be softened. Also report the MAML model pre-adaptation (`pre_adapt_acc`, already computed at `mamlpp.py:1128-1133` under debug) for comparison.
10. Coding rules for all of the above: no `dict.get` defaults, no swallowing `except`, no silent skipping of missing users/files; asserts for train/val/test/dev disjointness inside the split loader and the dataloader.
