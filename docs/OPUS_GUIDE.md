## Settled (do not relitigate)
- Protocol: 4 dev users (P005, P131, P116, P109) for HPO only, never in any reported result; 28 users in 7 folds of 20 train / 4 val / 4 test (`system/fixed_user_splits/kfold28_hpo4_split.json`, loader `kfold_split.py`). Dev users are excluded from all reported numbers; state that in the paper.
- Co-advisor approved: remove the label-permutation flag and always permute at test; one shared episode cache that every method consumes; raise on missing PIDs; carry rep ids; >=3 seeds for main methods; statistics on per-user means (28 users), never episodes.
- Data fact: the model input is one sample per whole repetition (10 reps/gesture/user, resampled to 64 steps; EMG is a 20 Hz envelope), not sliding windows. EMG is natively 2 kHz, 16 ch; IMU 148 Hz, 72 ch.
- Realised query size at eval is 10-K per class (9/7/5 for K=1/3/5), disjoint reps from support; documented as `B2` in the archived LIMITATIONS. Not a leak.
- Collection facts (Kai, 2026-10-21): **one session per participant; sensors were never taken off between reps/gestures; later-numbered repetitions were recorded later** (Gesture_Num is chronological); reps of a gesture were probably back-to-back (Kai unsure; `inspect_rep_structure.py` output pending). Gestures last about 0.5-3 s with some outliers. **Kai's decision: NO ordered/temporal support-query split.** All reps were recorded within roughly 1-5 minutes in one session, so rep order carries no meaningful drift; support/query reps are drawn at random (the co-advisor suggested ordered as a main result; Kai overrode it). Consequences: cross-session evaluation is impossible with this data and the paper must say so (same-session, minutes-scale limitation; no cross-session claims).
- EMG was recorded at **2048 Hz** per Kai, but the preprocessing code uses `FS=2000` (`build_2khz_tensor_dict.ipynb`, `emg_segraw_moments_pipeline.ipynb`): a 2.4% frequency-axis error in filters and spectral moments. **UPDATE (Sonnet, measured on the raw files, `docs/diag_2khz_all.json`):** segments are tightly cut around the gesture (median active fraction 97%, rest margins ~0.03 s), median length 3.2 s (p10 2.1, p90 4.8, max 12.2 s), so no trimming is needed, but the old 4300-sample resample time-warps the median trial 1.5x. The data contain no mains line, so the true sampling rate (2048 vs 2000) cannot be read from the signal; 2048 is kept. Recording structure from file-name timestamps: each gesture is one contiguous block of 10 reps ~5 s apart (a gesture's reps span a median 90 s); a whole session is a median 19.5 min. P4 is implemented as EMG-FS64 (see FULL_RUNNING_LOG).
- `q_query` is a TRAINING-only cap; eval always scores all non-support reps (Q = 10-K). The old `q_query_eval_mode` switch was deleted (2026-10-21); do not reintroduce a fixed Q across K.
- Kai is not wedded to EncoderMoE; fix it and pursue alternatives in parallel. Target venues in order: ICML (Jan) -> IMWUT/ASSETS -> CHI/NeurIPS -> IEEE Sensors.

### P1. Episode generator + cache design  -> `docs/SPEC_episode_cache.md`   (everything depends on this)
Decide: episode file format (one file per fold x split x seed? parquet/npz/pt), what is stored (user, class ids, per-episode label permutation, support/query *rep ids*, not tensors), how every method (neural MAML, supervised fine-tune, `$B`, kNN, ProtoNet, Riemannian, ROCKET, transformers) consumes it, how the file hash is stamped into each results JSON, and the asserts (disjoint users; disjoint support/query reps; hash match across methods). One sampler only: **random** reps (no ordered variant; Kai's decision). Decide how K=1..5 and N=3/5/10 grids are enumerated and how many episodes per (user, K, N) are cached; episodes within a user are heavily correlated, so the unit of analysis is the user. Current sampler for reference: `system/MAML/maml_data_pipeline.py:389-503`; baseline samplers that differ: `system/nonparametric/eval_knn_proto.py`.
### P2. Evaluation-protocol decisions after Kai's session answers  -> `docs/SPEC_protocol.md`
Inputs now known (see Settled): single session, no doffing, chronological rep index. Decide: how to present same-session, minutes-scale results honestly given no cross-session data exists (limitations wording; what claims the data cannot support); how to word the "user-defined gestures" claim. Only open fact: whether reps were strictly back-to-back (`inspect_rep_structure.py` output will come via Kai).
### P3. Zero-shot cross-user experiment  -> `docs/SPEC_zeroshot.md`
Design the experiment (train 10-way on a fold's 20 users with global labels, test new users with no support): pooled and **per-gesture** accuracy, plus a representation-level version (nearest class centroid from training users' embeddings, not head-confounded). Note MAML pre-adaptation accuracy is chance by construction under permutation, so it is not a zero-shot measure. **Write the framing consequence for each outcome range (~10% vs ~40%) BEFORE any number exists** and commit it in the doc.
### P4. 2 kHz EMG representation  -> `docs/SPEC_2khz_emg.md`
Choose between: modality-specific EMG stem before the EMG/IMU concat (T alignment with IMU; note the existing `front_end_stride` in `system/MOE/MOE_encoder.py:809` is applied after concat and cannot do this); windowed Khushaba spectral moments as a *sequence* (keeps CNN/LSTM sensible; code in `system/universal_preprocessing/EMG_preprocessing/from_original_repo/segraw_featureengr.py`, `shared_processing.py:176`); envelope-rate sweep {20,50,100,200} Hz. 2 kHz dict `segfilt_2khz_emg_tensor_dict.pkl` has 4300 samples/trial (full-trial `scipy.resample` time-warp, EMG only). Specify alignment/normalisation and the experiment order. Also decide the future of A10-A12/A11b (Kaifosh/Meta foundation model comparison, currently unwired and erroring under the new protocol).
### P5. Expert restructuring / MoE compute  -> `docs/SPEC_moe_compute.md`
Root cause of the 2 kHz OOM: every expert is computed for every sample (`torch.stack` over all E at `MOE_encoder.py:710,949,1145,1337,1618,1643`; memory O(B*E*C*T), independent of top_k). Sonnet will do the safe running-sum rewrite (identical math). You decide beyond that: chunking + `torch.utils.checkpoint`, shared early layers + per-expert late layers, small-k / top-1 routing (changes semantics), Soft-MoE slot routing, true sparse dispatch (blocked by `B14`: an expert with zero samples gets no gradient under MAML). Also specify the transformer variants Kai wants (transformer experts; transformer replacing the LSTM; both; a single non-MoE transformer) incl. interface constraints (`forward(x_emg, x_imu, demographics, return_routing)`, `torch.func.functional_call` compatibility).
